# 리더별 상황 시나리오 설계 (v0.2)

> 대상: Hyperithm 팀장 3명, 셀 리더 6명
> 기준 조직도: 공개 채용 페이지의 팀·셀 소개 (DeFi팀, 자산운용팀, 테크팀)
> v0.2: 전 CTO 회고 기반 시나리오 15개와 게임 메커닉 4개 추가 (8장)

---

## 1. 설계 원칙

1. **정답이 없는 딜레마:** 모든 선택지는 무언가를 얻고 무언가를 잃는다. "착한 답"이 뻔히 보이면 학습이 일어나지 않는다.
2. **현업과 같은 결:** 디페그, 익스플로잇, 키 관리, 봇 오작동처럼 실제로 겪을 수 있는 상황을 쓴다. 수치는 모두 가상이다.
3. **지연 효과:** 일부 선택은 몇 라운드 뒤에 결과가 드러난다(🕒 표시). 단기 성과와 장기 신뢰 사이의 긴장을 체감하게 한다.
4. **역할 간 연결:** 한 리더의 선택이 다른 팀의 상황을 바꾼다. 크로스팀 시나리오에서는 리더들이 함께 플레이한다.
5. **디브리프 중심:** 게임은 대화를 시작하는 도구다. 시나리오마다 회고 질문을 둔다.

## 2. 게임 지표와 리더십 역량

### 2.1 지표 (각 0–100, 시작값 50)

| 지표 | 의미 |
|---|---|
| 💰 수익 | 팀의 PnL, 수익 기회 실현 |
| 🛡️ 안정성 | 자산 안전, 리스크 한도 준수, 시스템 안정성 |
| 🤝 팀 신뢰 | 구성원의 심리적 안전감, 사기, 리더에 대한 신뢰 |
| 🔗 협업 | 다른 팀·셀과의 관계 |
| ⚡ 실행 속도 | 기회를 잡고 실행하는 속도 |

선택지 효과는 `+1` ~ `+3`, `-1` ~ `-3` 단계로 표기한다. 1단계 = 6점(데모 기준, 밸런싱 시 조정).

### 2.2 리더십 역량 태그

| 태그 | 역량 |
|---|---|
| `결단` | 불확실성 아래 의사결정 |
| `위기` | 위기 대응과 우선순위 판단 |
| `소통` | 투명한 정보 공유, 메시지 전달 |
| `코칭` | 피드백, 성장 지원, 성과 관리 |
| `위임` | 권한 이양과 신뢰 |
| `조율` | 이해관계자·팀 간 갈등 조정 |
| `원칙` | 리스크·보안 원칙을 지키는 힘 |

## 4. DeFi팀

### D-1. 디페그의 밤 · `시장 급변` · DeFi 팀장

**상황:** 밤 11시. 큐레이팅 중인 렌딩 볼트의 주요 담보 스테이블코인이 0.97달러까지 떨어졌다. 볼트에는 팀 운용 자산의 30%가 들어가 있다.

**압력**
- 큐레이션 셀 리더: "과거 패턴상 24시간 안에 복구됩니다. 지금 빼면 손실이 확정돼요."
- 월렛 셀 리더: "출금 큐가 막히기 시작했습니다. 늦으면 원할 때 못 뺍니다."
- 셀 리더 두 사람 모두 팀장의 결정을 기다리고 있다.

| 선택 | 효과 |
|---|---|
| A. 즉시 전액 출금 | 🛡️+3 💰-2 🤝-1 (큐레이션 셀은 판단을 무시당했다고 느낌) |
| B. 절반만 출금, 0.95 이하면 나머지도 출금하는 트리거 설정 | 🛡️+1 💰-1 🤝+1 |
| C. 손실 한도만 정해 주고 판단은 두 셀 리더에게 위임 | 🤝+2 ⚡-1, 🕒 두 셀이 합의에 실패하면 다음 라운드 🛡️-2 |
| D. 유지 | 💰+2 또는 💰-3 🛡️-3 (확률 이벤트) |

**회고 질문**
- 상충하는 전문가 의견 사이에서 무엇을 기준으로 결정했나?
- 결정의 이유를 두 셀 리더에게 어떻게 설명할 것인가?

### D-2. 1주일 안에 새 체인 · `팀 간 갈등` · DeFi 팀장

**상황:** 아비트라지 셀이 새 L2 체인에서 큰 가격 차이를 발견했다. 기회는 2–3주 안에 닫힐 것으로 보인다. 신규 체인 서명 인프라가 필요한데, 월렛 셀은 보안 검토에 최소 3주가 걸린다고 한다.

**압력**
- 아비트라지 셀: "이번 분기 목표의 절반이 여기 걸려 있습니다."
- 월렛 셀: "검토 없이 키를 붙이는 건 저희 이름으로 책임질 수 없습니다."

| 선택 | 효과 |
|---|---|
| A. 소액 한도의 임시 지갑으로 먼저 진입, 검토는 병행 | 💰+2 ⚡+2 🛡️-1, 🕒 10% 확률로 보안 이벤트 발생 |
| B. 보안 검토 완료 후 진입 | 🛡️+2 💰-2, 아비트라지 셀 🤝-1 |
| C. 아비트라지 셀 엔지니어 1명을 월렛 셀에 붙여 검토 기간 단축 | ⚡+1 🔗+2 💰-1 (기존 전략 운영 공백) |
| D. 두 셀 리더를 한자리에 모아 직접 합의안을 만들게 함 | 🤝+1 🔗+1, 합의 결과에 따라 A~C 중 하나로 이어짐 |

**회고 질문**
- 속도와 안전이 충돌할 때 팀의 원칙은 무엇인가? 그 원칙은 문서로 있는가?

### WA-1. 금요일 밤의 피싱 · `보안 사고` · 월렛 셀 리더

**상황:** 금요일 밤 10시. 멀티시그 서명자 중 한 명이 피싱 의심 메일의 링크를 클릭했다고 신고했다. 유출 여부는 아직 모른다. 키를 교체하려면 모든 전략을 4시간 멈춰야 한다.

**압력**
- 아비트라지 셀: "주말 변동성 장이 이제 막 시작됐습니다."
- 신고한 서명자: 극도로 자책하고 있다.

| 선택 | 효과 |
|---|---|
| A. 즉시 전체 중단, 키 교체 | 🛡️+3 💰-2 🔗-1 |
| B. 해당 서명자만 멀티시그에서 제외, 전략은 유지 | 🛡️+1 💰 0 (임계값 여유가 있을 때만 가능) |
| C. 조사 결과가 나올 때까지 신규 트랜잭션 한도만 축소 | 💰-1 🛡️ 0, 🕒 실제 유출이었다면 🛡️-3 |

**추가 판단:** 신고한 서명자를 어떻게 대할 것인가? (공개 감사 표시 / 조용한 위로 / 언급 안 함) → 🤝 및 향후 신고 문화에 영향

**회고 질문**
- 신고한 사람이 벌을 받는다고 느끼면 다음 사고는 신고될까?

## 7. 크로스팀 시나리오

전원이 동시에 플레이한다. 라운드마다 각자 결정을 내린 뒤, 결과가 다른 팀의 다음 라운드 상황을 바꾼다.

### X-1. 블랙 먼데이 · `시장 급변` · 3라운드

**상황:** BTC가 2시간 만에 25% 하락했다.

| 라운드 | DeFi팀 | 자산운용팀 | 테크팀 |
|---|---|---|---|
| 1 (0–30분) | 볼트 담보 청산 급증, 가스비 10배 | 포지션 대규모 손실, 롱 청산 위험 | 메시지 큐 지연, 알림 폭주 |
| 2 (30–90분) | 아비트라지 기회 폭증, 하지만 월렛 셀 트랜잭션 처리 한계 | 저점 매수 기회 vs 리스크 한도 소진 | 어느 팀 트래픽을 먼저 처리할지 결정 |
| 3 (사후) | 셀 간 책임 공방 | 엔지니어링 셀과 크립토 셀의 회고 | 전사 회고 발표 |

**공유 자원 (협상 대상)**
- 테크팀 엔지니어 시간: 라운드당 3단위
- 회사 전체 리스크 한도: 남은 여유 100단위
- 월렛 셀 트랜잭션 처리량: 라운드당 5건

**핵심 학습:** 내 팀의 최적화가 회사 전체의 최적화와 다를 수 있다. 협상하지 않은 팀은 자원을 받지 못한다.

---

### X-2. 프로토콜 익스플로잇 · `보안 사고` · 2라운드

**상황:** DeFi팀이 큐레이팅 중인 렌딩 프로토콜이 해킹당하고 있다는 온체인 신호가 잡혔다. 아직 공식 발표는 없다.

- **DeFi팀:** 남은 자산을 얼마나 빨리 뺄 수 있나? 다른 예치자들에게 알릴 것인가?
- **자산운용팀:** 해당 프로토콜 토큰 숏은 수익 기회다. DeFi팀의 정보를 먼저 받아서 써도 되는가?
- **테크팀:** 이상 거래 감지 봇의 신호를 어느 팀에 먼저 줄 것인가?

**핵심 학습:** 팀 간 정보 공유의 속도와, 정보 사용의 윤리·컴플라이언스 경계. 정답보다 "우리 회사의 원칙은 무엇인가"를 합의하는 과정이 목표다.

### R-1. 범용 거래소 연동 프레임워크 · `기술 결정` · 테크 팀장 / 엔지니어링 셀 리더
📖 1장 테크 리딩

**상황:** 거래소 3곳과 새로 연동해야 한다. 팀의 가장 뛰어난 엔지니어가 "앞으로 거래소는 계속 늘어나니, 어떤 거래소든 붙일 수 있는 추상화 레이어를 먼저 만들자"고 제안한다. 설계 문서는 아름답고, 예상 기간은 3개월이다.

| 선택 | 효과 |
|---|---|
| A. 범용 추상화 레이어부터 구축 | ⚡-1, ❄️ 6라운드 후 "코드베이스 전면 폐기" 이벤트 확률 50% (💰-3 🤝-2) |
| B. 거래소 3곳을 각각 직접 구현, 공통점은 나중에 추출 | ⚡+2 🛡️ 0, 엔지니어 🤝-1 (제안이 거절됨) |
| C. 📚 사례 카드 사용 후 결정 | 공개 정보: "다른 회사에서도 이 방식으로 반년을 날린 사례가 있다" |

**회고 질문**
- 우아한 설계와 당장 필요한 기능 사이에서 무엇을 근거로 판단했나?
- 이 결정을 되돌리는 데 비용이 얼마나 드는가?

### R-2. 직접 만들 것인가 · `기술 결정` · 월렛 셀 리더
📖 1장 테크 리딩 (오픈소스 vs SaaS vs 직접 구현)

**상황:** 서명 키 관리 시스템을 새로 고쳐야 한다. 선택지는 셋이다. 검증된 오픈소스, 외부 커스터디·MPC SaaS, 직접 구현. 셀원들은 "써본 적 없는 스택은 불안하니 직접 만들자"고 한다.

| 선택 | 효과 |
|---|---|
| A. 직접 구현 | 🤝+1 (통제감) ⚡-2, ❄️ 유지보수 부담 누적 |
| B. 검증된 오픈소스 + 자체 보안 검토 | 🛡️+1 ⚡+1 |
| C. 외부 SaaS 도입 | ⚡+2 🛡️ ±? (벤더 락인, 외부 의존 리스크 이벤트) |

**회고 질문**
- "직접 만들면 통제할 수 있다"는 느낌은 실제 통제력인가, 경험 부족에서 온 불안인가?

### R-3. 팀원들이 납득하지 않는다 · `소통` · 모든 팀장
📖 1장 "팀원이 납득하지 못하는 기술적 결정은 매우 높은 확률로 틀렸다"

**상황:** 리더가 2주 동안 검토해 결정한 방향(예: 레거시 인증·RPC 구조 교체 방식)을 발표했다. 회의 분위기가 싸늘하다. 반대 의견은 나오지 않았지만, 다음 날부터 진행이 눈에 띄게 느리다.

| 선택 | 효과 |
|---|---|
| A. 이미 검토가 끝난 결정이니 그대로 진행 | ⚡+1 🤝-2, 🕒 결정이 틀렸을 확률 공개 이벤트 |
| B. 반대 의견을 가진 팀원과 1:1로 이유를 듣기 | 🤝+2 ⚡-1, 숨겨진 반례 1개 공개 |
| C. 설명 자료를 다시 만들어 재발표 | 🤝+1 ⚡-1 |

**디브리프 포인트:** 회고는 원인을 셋으로 본다. 내가 틀렸거나, 설명을 못 했거나, 팀원 수준이 낮거나. 그리고 "결국 셋 다 본인 문제"라고 결론 낸다.

### R-4. 누더기 API · `팀 간 갈등` · 테크 팀장 + 자산운용 팀장 (2인)
📖 2장 매니징 "애드혹한 요청을 하는 팀과 애드혹하게 해결하는 팀"

**상황:** 지난 3개월 동안 트레이더들이 플랫폼 셀 엔지니어에게 DM으로 직접 요청한 작은 기능이 23개다. 하나씩은 30분짜리 일이지만, 지금 API는 아무도 전체를 설명하지 못한다. 모아 놓고 보니 "확장 가능한 스키마의 데이터베이스와 CRUD 서비스" 하나로 대부분 해결될 문제였다.

| 선택 (테크 팀장) | 효과 |
|---|---|
| A. 지금처럼 요청이 오는 대로 처리 | 🔗+1 ⚡+1, ❄️ 누더기 API 누적 |

### R-14. 이건 우리 일이 아닌데요 · `비전` · 테크 팀장

### R-15. 우리는 갈라파고스인가 · `변화 관리` · 크로스팀 (전원)

**상황:** 컨퍼런스에서 만난 다른 회사 엔지니어가 "코딩 에이전트를 지금 도입하지 않으면 뒤처진다"고 몇 시간 동안 설명했다. 트레이더들이 직접 봇을 바이브코딩하게 되면 생산성이 크게 오를 수 있다. 하지만 전략 코드와 키 관련 정보가 외부 모델로 나갈 수 있다.

| 플레이어 | 결정 |
|---|---|
| 테크 팀장 | 사내 지식베이스에 연결된 에이전트 플랫폼 구축을 주도할 것인가 |
| 월렛 셀 리더 | 보안 기준을 어디까지 허용할 것인가 (거부권 보유) |
| 자산운용 팀장 | 트레이더의 바이브코딩 봇을 실거래에 얼마나 허용할 것인가 |
| DeFi 팀장 | 전략 코드의 외부 모델 사용 범위 |

**결과:** 모두 보수적이면 🛡️+2, 🕒 경쟁력 하락 이벤트 (💰-2). 모두 공격적이면 ⚡+3 💰+1, 🎲 보안 사고 확률 30%. 보안 기준에 합의한 단계적 도입이면 ⚡+2 🛡️+1.

**핵심 학습:** 외부 탐색(기술 블로그, 다른 회사와의 커피챗)은 시간이 남을 때 하는 일이 아니라 의도적으로 해야 하는 투자다.

테크팀 쪽에 시나리오가 몰려 있다. 회고가 개발 조직 관점이기 때문이다. 트레이딩 쪽 셀 리더용 시나리오는 실제 리더 인터뷰로 보강하는 것이 좋다.

## 9. 열린 질문

- 실제 팀·셀 구성과 리더 역할 확인 (공개 자료로는 테크팀의 트레이딩 플랫폼 외 셀 구성을 알 수 없음)
- 확률 이벤트(🎲)의 확률값과 지표 1단계 점수 밸런싱 (데모에서는 결과를 고정해 반복 플레이 시 같은 결과가 나오도록 함)
- 시나리오 순서: 개인 시나리오 2–3개 → 크로스팀 1개 구성의 한 세션(약 90분)을 기본안으로 제안
